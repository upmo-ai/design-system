The compositions tier assembles the primitives into the patterns pages are built
from: the page frame, panels, tables, empty states, code blocks, breadcrumbs,
menus, and dialogs. They follow the patterns rules: one primary action per
region, actions right-aligned, and a clear confirm for destructive actions.

:::tip[Live previews are in Storybook]
Every component renders live, in light, dark and high contrast, in the
[Storybook gallery](https://design.upmo.dev/storybook/). Run it locally with
`pnpm --filter @upmo-ai/storybook dev`.
:::

## AppFrame, SideNav and NavItem

`AppFrame` is the product frame around `PageShell`, built on Mantine
`AppShell`. It has four slots: `header` (top of the side rail: the wordmark and
workspace name), `navigation` (a `SideNav`), `footer` (the account menu and
theme switch) and `topBar` (breadcrumbs, search, the notifications bell). The
page goes in `children`.

- **From md**: the full sidebar. The top bar toggle collapses it to the icon
  rail (`collapsed`, `defaultCollapsed`, `onCollapsedChange`).
- **Between sm and md**: the icon rail; the toggle opens the full navigation as
  a drawer.
- **Below sm**: no rail; the toggle opens the drawer. The drawer traps focus,
  closes on Escape or the scrim, and closes when an item is chosen.

`SideNav` is the `<nav>` landmark. `NavSection` groups items under an optional
label, which becomes a divider in the rail. `NavItem` takes a `label`, an
`icon`, `href` or a router `component` with `linkProps`, `active` (marks
`aria-current="page"`), and an optional `count` or `badge`. Give it nested
`NavItem`s to make a collapsible group; in the rail a group opens as a flyout
menu, and a group nested inside it opens as a submenu. In the rail the label becomes the tooltip and stays the accessible name.
A group's `opened`, `defaultOpened` and `onOpenedChange` are its expanded state
in the full sidebar and the drawer; the rail flyout and its submenus open on
demand with their own state and do not call `onOpenedChange`. `onClick` is
called in every layout, the flyout trigger included.
Slots that adapt to the rail read `useAppFrame().rail`; inside the drawer it is
always `false`, so the header shows in full there.

The drawer is always as tall as the viewport, with the whole navigation in it
and the `footer` slot pinned to the bottom edge. Its layout class
(`upmo-app-frame__drawer`) sits on the Mantine Drawer content only; the
full-viewport `.mantine-Drawer-inner` wrapper keeps Mantine's own layout. Before
this was fixed (1.1.1), the class also landed on the wrapper and the drawer
measured about 248px tall with the navigation cut off.

:::note[Dropping the old workaround]
If your app carries the workaround rule
`.mantine-Drawer-inner.upmo-app-frame__drawer { flex-direction: row; background: none }`,
it is harmless now: the wrapper no longer has the class, so the rule matches
nothing. You can delete it.
:::

The frame's CSS uses logical properties, and the rail tooltips and flyouts sit
at the inline end: for right-to-left, set `dir="rtl"` and wrap the app in
Mantine's `DirectionProvider`, which flips them to the left.

```tsx
<AppFrame
  header={<Brand />}
  footer={<AccountMenu />}
  topBar={<TopBar />}
  navigation={
    <SideNav>
      <NavSection>
        <NavItem label="Tasks" icon={<Icon concept="nav.tasks" />} component={Link} linkProps={{ to: '/tasks' }} active count={3} />
      </NavSection>
      <NavSection label="Workspace">
        <NavItem label="Management" icon={<Icon concept="nav.settings" />} defaultOpened>
          <NavItem label="Members" component={Link} linkProps={{ to: '/admin/members' }} />
        </NavItem>
      </NavSection>
    </SideNav>
  }
>
  <PageShell header={{ title: 'Tasks' }}>{page}</PageShell>
</AppFrame>
```

### Controlling the drawer

Below md the toggle opens the drawer. The frame keeps that state itself, and you
can hold it instead: `drawerOpened` and `onDrawerOpenedChange` control it, and
`defaultDrawerOpened` sets the starting state when you leave it uncontrolled.
`onDrawerOpenedChange` is called for every way the drawer opens or closes: the
toggle, Escape, the scrim, the close button, a chosen `NavItem`, `closeDrawer()`
from `useAppFrame()`, and the viewport widening to md with the drawer open. From
md there is no drawer, so `drawerOpened` is ignored there; the rail stays
available and the toggle collapses it as before.

If the viewport widens past md while the drawer is open, the drawer closes, the
rail behind it stops being inert, and narrowing again does not bring the drawer
back. When focus was inside the drawer, it moves to the navigation toggle in the
top bar, so the next Tab continues from there and not from the top of the page.

### The navigation shortcut

The frame does not bind a keyboard shortcut. Ctrl+B or Cmd+B is common for
toggling navigation, and it stays in your app, where you know what else claims
the key. The controlled props make it short to write: collapse the rail from
md, toggle the drawer below it.

```tsx
const theme = useMantineTheme();
const wide = useMediaQuery(`(min-width: ${theme.breakpoints.md})`, true, { getInitialValueInEffect: false });
const [collapsed, setCollapsed] = useState(false);
const [drawerOpened, setDrawerOpened] = useState(false);

useEffect(() => {
  const onKey = (e: KeyboardEvent) => {
    if (e.key.toLowerCase() !== 'b' || !(e.metaKey || e.ctrlKey)) return;
    if (e.altKey || e.shiftKey || e.repeat || e.isComposing) return;
    e.preventDefault(); // Firefox: Ctrl+B opens the bookmarks sidebar
    if (wide) setCollapsed((c) => !c);
    else setDrawerOpened((o) => !o);
  };
  window.addEventListener('keydown', onKey);
  return () => window.removeEventListener('keydown', onKey);
}, [wide]);

<AppFrame
  collapsed={collapsed}
  onCollapsedChange={setCollapsed}
  drawerOpened={drawerOpened}
  onDrawerOpenedChange={setDrawerOpened}
  /* header, navigation, footer, topBar */
>
  {page}
</AppFrame>
```

Three things to know:

- Keydown events still reach `window` while the drawer traps focus, so the same
  shortcut closes it. Focus returns to what had it before the drawer opened.
- Skip the shortcut inside rich-text editors, where Ctrl+B means bold.
- Use the same `md` breakpoint as the frame, so the shortcut and the toggle
  always agree on whether there is a drawer.

### A page that fills the main region

By default `main` is a padded column that grows with the page. Set `fill` for a
page that owns its height, such as a chat. Main then becomes a viewport-tall
column without padding, and it scrolls if its content overflows. Children keep
their own height except the last one, which grows to fill what is left. Alerts
or offers above it keep their size. `mainClassName` adds your class to the main
region for anything else.

```tsx
<AppFrame fill mainClassName="chat-main" /* ... */>
  {banner}
  <section className="chat-page" aria-label="Messages">
    <div className="chat-thread">{messages}</div>
    <Composer /* ... */ />
  </section>
</AppFrame>
```

The last child grows to fill the space, but it cannot shrink below its content.
So the page has to let its scrolling part give way. Put `min-height: 0` on the
page and `flex: 1 1 0` on the part that scrolls (the thread), and leave the
composer at its natural height:

```css
.chat-page {
  display: flex;
  flex-direction: column;
  min-height: 0;
}
.chat-thread {
  flex: 1 1 0;
  min-height: 0;
  overflow-y: auto;
}
```

With a plain `overflow-y: auto` thread and no `flex: 1 1 0`, the thread grows to
the height of all its messages, main scrolls instead, and the composer scrolls
out of view.

Things to know:

- Fill the space with the last child. A trailing portal or a hidden live region
  rendered as the last child would take the space instead, so render those
  earlier or inside the page.
- The styles for `fill` have zero specificity, so your own rules on the page and
  on `mainClassName` always win.
- Main starts at the top of the window, under the fixed top bar. It sets
  `scroll-padding-top` to the bar's height, so a focused control that main
  scrolls into view stops below the bar and not behind it.
- Switching `fill` on does not animate main's padding. Mantine slides it when
  the rail collapses; with `fill` the padding is a layout switch between
  routes, so it changes at once. Switching `fill` off again still slides the
  padding back in.

## Wordmark

The Upmo wordmark as an inline SVG: "up" and the caret in the brand emerald,
"mo" in ink, read from tokens so it is correct in light, dark and high contrast.
`compact` gives the caret mark alone, for the collapsed rail; `height` sizes it
(default 24). It is a named image ("Upmo" by default, `label` to change it).
Inside a link or button that already has a name (a "Home" link), set
`decorative`: it is then hidden from assistive tech, with no role or name.

```tsx
function Brand() {
  const { rail } = useAppFrame();
  return <Wordmark compact={rail} />;
}
```

## StatusAlert

An inline message for a region or page. `tone` is `info`, `positive`,
`attention` or `critical`, mapped onto the status tone layer (info is the
neutral, info-blue tone). Every tone carries its own icon, so colour is never
the only signal. Add a `title`, `actions` (one or two small buttons) and
`onDismiss` for a labelled close button ("Dismiss", or `dismissLabel`).
Critical alerts use `role="alert"` and are announced at once; the others use
`role="status"`. Override with `role` when a warning is urgent.

```tsx
<StatusAlert tone="critical" title="Provider rejected the key" onDismiss={hide} actions={<Button size="xs">Replace key</Button>}>
  Anthropic answered 401. Agents using it are paused.
</StatusAlert>
```

## PageHeader and PageShell

`PageHeader` is the title (h1) plus an optional description on the left, and
right-aligned actions. `PageShell` is the inner page frame: a padded column with
an optional header and a consistent gap to the content.

## Panel and Card grid

`Panel` is a bordered, flat surface (no resting shadow). Lay panels out with a
`SimpleGrid`.

## Table

A dense data table with a sticky header on the sunken ground. Use `Table.Num`
for right-aligned tabular figures and `Table.Mono` for ids and keys. Wrap in
`Table.ScrollContainer` for narrow screens.

### DataTable

`DataTable` adds a toolbar (search and a filter slot) and a footer (summary and
pagination) around `Table`. Give every table a name, so a screen reader user can
find it among the tables on a page. Three ways, in order of preference:

- `caption` shows a visible caption above the rows and names the table with it.
- `aria-labelledby` points at a heading above the table.
- `aria-label` names the table when there is no visible text to point at.

Nothing warns when the name is missing, so check it yourself.

`minWidth` is the width, in px or any CSS length, below which the table scrolls
sideways instead of squeezing its columns. It defaults to 480. A table with two
short columns can use a smaller value, so it does not scroll on a phone.

The scrolling part is a tab stop, so a keyboard user can focus it and scroll
sideways with the arrow keys, even when no cell has a link or a button. It is a
region that carries the table's name, and it shows the focus ring when focused.
An unnamed table is still a tab stop, but is not announced as a region.

```tsx
<DataTable
  caption="Remembered facts"
  minWidth={320}
  columns={columns}
  rows={rows}
  rowKey={(row) => row.id}
/>
```

## Composer

The chat input: an autosizing textarea over a toolbar of pills. The config pill
fans out to nested menus (Agent, Route, Model); the tools pill picks the tools
mode.

Give an option a `description` and the menu shows it under the label, in quiet
type. It is the item's accessible description, so the name stays the label
("Fast", not "Fast, answers sooner") and queries by name keep working. Each
group in the config menu shows its current value at the end of its row, again as
a description: the item is still named "Agent".

```tsx
<Composer
  value={draft}
  onChange={setDraft}
  onSend={send}
  config={{
    label: 'Agent, route and model',
    groups: [
      {
        label: 'Route',
        value: route,
        onChange: setRoute,
        options: [
          { value: 'default', label: 'Default', description: 'Balanced speed and depth.' },
          { value: 'fast', label: 'Fast', description: 'Answers sooner, with less depth.' },
        ],
      },
      // Agent, Model
    ],
  }}
/>
```

### Grouped and searchable options

A long list, such as models from several providers, can be organised in its
config group:

- `group` on an option puts consecutive options with the same value under one
  section label. Options without `group` have no label.
- `pinned` on an option keeps it at the top, above every label. A pinned option
  is never filtered out. The design system gives no option special treatment, so
  set `pinned` on your own "Auto" row.
- `searchable` on the group adds a filter field at the top of its menu, named
  "Filter" plus the group label. It matches the label and the description,
  ignoring case, hides labels with no matching option, and shows "No matches"
  when nothing is left. Opening the submenu from the keyboard puts focus in the
  field, so typing filters at once, and the arrow keys still move through the
  options (Enter picks one). The text clears when the menu closes.

```tsx
{
  label: 'Model',
  value: model,
  onChange: setModel,
  searchable: true,
  options: [
    { value: 'auto', label: 'Auto', pinned: true },
    { value: 'opus', label: 'Claude Opus', group: 'Anthropic' },
    { value: 'gpt', label: 'GPT', group: 'OpenAI' },
  ],
}
```

### Narrow widths

The toolbar wraps instead of clipping, and a long pill label ends in an
ellipsis. `toolbar` sets how much shows:

- `"auto"` (the default) goes compact when the composer is narrower than 420px.
- `"compact"` is always compact, `"full"` never is.

In the compact toolbar the config pill shows the model instead of the whole
selection: the selected label of the last group, or
`compactSummary` on the config when you want other text. The pill is named by
its label and the text it shows, for example "Agent, route and model: Claude
Sonnet", so what a person sees is part of the name and "click Claude Sonnet"
works by voice. The full selection ("Auto · Fast · Claude Sonnet") is the pill's
description. The full toolbar names the pill with the full selection and has no
description. Send keeps its place at the end of the first line.

The toolbar layout changed in this release; see
[Composer toolbar layout](/compositions/composer-layout/).

The width is measured after the first render, so the first paint is the full
toolbar. If you know the composer is narrow, say `toolbar="compact"` to skip
that step.

## EmptyState

An icon tile, a title, a supporting line, and at most one primary action. Use
`firstRun` for the dashed invitation border.

`compact` tightens the padding, shrinks the tile to 32px, sets the title at the
h4 size and lets the supporting line use the full width, so the state fits a
320px popover or a small panel. `headingLevel` (2 to 6, default 3) sets the
semantic level of the title without changing how it looks: the size stays h3, or
h4 when compact. Put the title where it belongs in the page outline.

```tsx
<EmptyState compact headingLevel={4} title="You are all caught up" description="Nothing needs your attention." />
```

## CopyButton and CodeBlock

`CopyButton` copies to the clipboard and confirms with a brief "Copied" state.
`CodeBlock` shows monospace code on a sunken ground with a copy affordance;
`JsonBlock` pretty-prints a value.

## ConfirmDialog

Asks before an action. The body spells out the consequence; the confirm button
names the outcome ("Remove member"). Destructive confirms turn the confirm
button red, and still name the consequence, colour is never the sole signal.
Cancel is the safe default; prefer undo over confirm where the action is safely
reversible.

## BrandMark

`BrandMark` draws a service's official mark from `@upmo-ai/brands`, inline, in
its own colours (`monochrome` uses the text colour instead). The `brand` id is
case-insensitive. Some services also answer to the id people tend to type:
`gemini` resolves to the `googlegemini` mark, `google-calendar` to
`googlecalendar` and `google-drive` to `googledrive`. The alias map is exported
from `@upmo-ai/brands` as `aliases`. An unknown id shows a plug (connector) or
server (provider) glyph. A mark for a service that is not in the package is not
drawn by hand: it is added only from the brand's own published artwork.

```tsx
<BrandMark brand="google-drive" size={28} />
<BrandMark brand="gemini" kind="provider" />
```

## Connect surfaces

The connect surfaces are the pieces of a "connect a service" flow:
`BrandTileGrid`, `ConnectWizard`, `TestConnectionPanel`, and the `ConnectorCard`
and `ProviderCard` that show what is already connected.

**BrandTileGrid** is the pick-a-service step. Each tile is a toggle button
(`aria-pressed`) named by the brand name alone, so a lookup such as
`getByRole('button', { name: 'OpenAI' })` finds it. The `adapter` and
`description` are the tile's accessible description (`aria-describedby`): they
stay visible, and a screen reader reads them after the name.

A selected tile keeps the emerald border and ground when you hover it, and only
an unselected tile takes the hover style. In forced-colors mode the selected
tile has a 2px `Highlight` border, so selection does not depend on colour.

**TestConnectionPanel** is the Test button and a status area. The button is as
wide as its label and starts at the left edge; the status area is always full
width. To stretch the button across the panel, add the `upmo-testconn--full-width`
class:

```tsx
<TestConnectionPanel state="idle" onTest={runTest} className="upmo-testconn--full-width" />
```

**ConnectorCard and ProviderCard** are built for a 320px grid cell, 288px of
content inside the padding. The status badge ("Connected", "Not connected")
keeps its content width and is never truncated; the title block gives up space
first, so a long name wraps beside the badge. The actions are small buttons on
one start-aligned row. They wrap onto a second row, still start-aligned, only
when the card is too narrow for both.

Both cards send their rest props, any prop the card does not use itself, to the
root `div`: `data-*`, `aria-*`, `role`, `style` and
event handlers. Their `id` is the connector or provider id (also the brand
key), not a DOM id, so it is not rendered.

```tsx
<ProviderCard id="openai" name="OpenAI" status="Connected" planKind="metered" data-testid="provider-openai" />
```

Four things to watch for:

- Do not spread a whole API object into the card, as in
  `<ConnectorCard {...connectorFromApi} />`. Fields the card does not know,
  such as `hidden`, `title` or `createdAt`, are forwarded to the DOM: `hidden`
  hides the card, `title` becomes a tooltip, and unknown fields raise React
  warnings. Pass the props you mean to.
- A click handler on the card (`onClick`) also receives clicks from the Edit
  and Disconnect buttons, because clicks bubble. Check `event.target`, or call
  `event.stopPropagation()` in the button handlers, if the card should react
  only to clicks on its own surface.
- `aria-label` needs a `role` on a plain `div`. Pair it with a valid role such
  as `role="group"`; on its own it is not valid ARIA.
- Avoid `role="button"` on the card: it would nest the Edit and Disconnect
  buttons inside a button.

```tsx
<ConnectorCard
  id="github"
  name="GitHub"
  resourceScope="all"
  changes="ask"
  role="group"
  aria-label="GitHub connector"
/>
```

**ConnectWizard** is a stepper that only goes back; forward movement comes from
your own Next buttons. Give a step `disabled` to lock it. A disabled step still
shows in the stepper, dimmed with a not-allowed cursor, but it cannot be
selected: a click does nothing, it is out of the tab order and it is exposed as
`aria-disabled`. Use it for edit
flows where the first step, the service, must not change. Start such a flow on
the step you want (`active={1}`); the wizard never moves `active` for you.

```tsx
<ConnectWizard
  active={1}
  onStepChange={setActive}
  steps={[
    { label: 'Tool', description: 'GitHub', content: <p>The service cannot change.</p>, disabled: true },
    { label: 'Authentication', content: <TokenStep /> },
    { label: 'Permissions', content: <ScopeStep /> },
  ]}
/>
```
