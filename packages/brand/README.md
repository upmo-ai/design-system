# @upmo-ai/brand

The Upmo brand asset kit: the wordmark and the caret mark as SVG in light, dark
and mono, plus the favicon, app icons and the social share image. It is files
only: no React and no runtime dependencies. Every file is generated from one
geometry source and the colour tokens, and committed.

## Install

```sh
pnpm add @upmo-ai/brand
```

## What is in the kit

SVG, in `svg/`. Each comes as `wordmark-<variant>.svg` and
`caret-<variant>.svg`:

| Variant | Colours |
| --- | --- |
| `light` | `emerald` and `ink` from the light theme, for light grounds. |
| `dark` | `emerald` and `ink` from the dark theme, for dark grounds. |
| `mono` | `currentColor`, so the mark takes the colour of the text around it. |
| `mono-black` | Black. |
| `mono-white` | White. |

For the site, in `web/`:

| File | Use |
| --- | --- |
| `favicon.svg` | The caret, recoloured for dark browsers. |
| `favicon.ico` | The caret at 16, 32 and 48 pixels, for browsers without SVG icons. |
| `apple-touch-icon.png` | 180 by 180, opaque, for the iOS home screen. |
| `icon-192.png`, `icon-512.png` | Web app icons. |
| `icon-512-maskable.png` | Web app icon with the mark inside the safe zone, for adaptive masks. |
| `og.png` | 1200 by 630 share image: the wordmark alone. |
| `site.webmanifest` | A web app manifest that lists the icons above. |
| `head.html` | The `<head>` tags that link the files above. |

The SVG files carry `role="img"` and the name "Upmo". Use the wordmark as an
image with that name, or hide it when a link beside it already says "Upmo".

## Usage

The package has no JavaScript entry point, so `import '@upmo-ai/brand'` fails
by design. Import a file by its subpath, and let your bundler turn the SVG into
a URL:

```tsx
import wordmark from '@upmo-ai/brand/svg/wordmark-light.svg';
import favicon from '@upmo-ai/brand/web/favicon.svg';
```

| Import path | File on disk |
| --- | --- |
| `@upmo-ai/brand/svg/<file>` | `node_modules/@upmo-ai/brand/dist/svg/<file>` |
| `@upmo-ai/brand/web/<file>` | `node_modules/@upmo-ai/brand/dist/web/<file>` |
| `@upmo-ai/brand/package.json` | `node_modules/@upmo-ai/brand/package.json` |

These three are the only exports. The published package holds `dist/` and
nothing else: the drawing source `src/geometry.ts` and the generator live in
the repository and are not installed.

To ship the site files with an app, copy `web/` into the folder your build
serves from the root, then paste `web/head.html` into the page head. Replace
`{{origin}}` with the absolute origin of the site, because share images need an
absolute URL.

```sh
cp -r node_modules/@upmo-ai/brand/dist/web/. public/
```

## Regenerate

In the repository, the files in `assets/` are generated by
`scripts/generate.ts` from `src/geometry.ts` (the wordmark and caret outlines)
and `@upmo-ai/tokens` (the colours). The build copies `assets/` into `dist/`. Do not edit them by hand. PNGs are drawn with a pinned
`@resvg/resvg-js`, and all text is already outlined, so no fonts are needed.

Run the generator in a container pinned to `linux/amd64`, so the PNG bytes match
CI:

```sh
docker run --rm --platform linux/amd64 -v "$PWD":/w -w /w node:24.22.1 sh -c \
  "corepack enable && pnpm install --frozen-lockfile && pnpm --filter @upmo-ai/brand generate"
```

Add `--check` to fail instead of writing when a file is out of date. CI does
this on every pull request.

The generator also keeps three copies in step for the docs site: its two header
logos and its favicon.
